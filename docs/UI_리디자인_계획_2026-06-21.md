# Sai UI 리디자인 계획 — 프리미엄 미스틱(B) (2026-06-21)

> 방향 확정: **B 프리미엄 미스틱**. 기능 로직은 손대지 않고 **CSS·마크업·테마**만 바꾼다.

## 1. 디자인 토큰 (단일 출처)

지금은 색·간격·라운드·그림자 값이 파일 곳곳에 하드코딩돼 있고 `.hero-title`처럼 같은 셀렉터가 6~8군데 중복·충돌한다. 먼저 **CSS 변수 1벌**로 토큰화해서 이후 모든 스타일이 이 변수를 참조하게 한다.

```css
:root{
  /* 배경 */
  --bg-deep:#1a0d1f;      /* 최심부 */
  --bg-base:#241327;      /* 기본 배경(현행 유지) */
  --bg-surface:#2f1c36;   /* 카드 표면 */
  --bg-sunken:#1c0e20;    /* 막대 트랙 등 함몰 */
  /* 골드 (정제) */
  --gold:#ecca7e;         /* 강조/타이틀 */
  --gold-soft:#cdb98f;    /* 보조 텍스트 */
  --gold-line:rgba(232,200,122,.30); /* 경계선 */
  /* 텍스트 (명도 상향 = 시인성) */
  --text:#f3e6c8;         /* 본문 (현행 #fef3c7보다 또렷) */
  --text-muted:#bfa884;   /* 캡션 (현행 #d6bd92/#c8b490 대비 보강) */
  /* CTA */
  --cta-a:#d99a36; --cta-b:#f0c060; --cta-ink:#3a2405;
  /* 형태 */
  --r-card:16px; --r-pill:999px;
  --glow:0 0 16px rgba(240,192,96,.30);
}
```

config.toml(`base/primaryColor/backgroundColor/...`)도 위 토큰과 일치하도록 미세 조정.

## 2. 파일·위치별 변경

### 2-1. `app.py` — 디자인 시스템 블록 (약 8285~8600줄)
- `:root` 토큰 블록을 최상단에 주입(현 `components.html` 주입 방식 그대로).
- 기존 색 하드코딩을 `var(--…)`로 치환. **`!important` 남발 정리**(필요한 곳만 유지).
- 본문/캡션 명도 상향: `.stMarkdown p`, `[data-testid=stCaptionContainer]`, 위젯 라벨.

### 2-2. `.hero-title` 중복 통합 (약 10563 / 12235 / 12445 등)
- 흩어진 정의를 **한 곳으로 통합** → 골드 글로우 + 골드 디바이더가 있는 단일 히어로 스타일. 충돌·예측불가 제거.

### 2-3. 메인 메뉴 카드화
- 평범한 알약 버튼 → **아이콘 + 한 줄 설명 카드**(진단/케미/맞짱/초대). 직관성·매력도 핵심.
- 큰 화면 하단 여백 과다 → 콘텐츠 최대폭·세로 리듬 조정.

### 2-4. 입력 화면
- 라벨→입력 한 줄 흐름으로 정돈, 한 칸 생년월일시(`single_birth_dt_text`) 유지, 앰버 CTA 강조.

### 2-5. 결과 화면(진단/케미/맞짱)
- 점수 크게 + 골드 글로우, 오행/케미 막대 트랙 대비 강화, 신살·칭호 카드 가독성↑, 랭킹 1위 강조.
- 관련 컴포넌트 CSS(`.element-bar-*`, `.chem-*`, `.daewun-flow-*`, `.shinsal-*`, `.pipeline-card` 등, 약 8604~)를 토큰 참조로 정리.

### 2-6. Flutter 스플래시 `saju_mri/lib/screens/splash_screen.dart` (약 60~110줄)
- **현재: 네이비(`#1A1A2E`) + 파랑(`#3B5BDB`) + "임시 아이콘"(self_improvement) + 옛 슬로건** → 웹과 단절.
- **변경: 플럼 그라데이션 배경 + 골드 이중 링 "Sai" + 슬로건 "Saju Analysis Interactive"**. 앱 첫인상을 본편과 통일.

## 3. 작업 순서 (단계별·검증 가능)

1. 토큰 블록 주입 + config.toml 정렬.
2. 타이포/명도/`.hero-title` 통합 (시인성).
3. 메인 메뉴 카드화 + 레이아웃 여백.
4. 입력 화면 정돈.
5. 결과·케미·맞짱 컴포넌트 정리.
6. Flutter 스플래시 교체.
7. 검증 → push(웹) / AAB 빌드(앱, 사용자).

각 단계 후 화면 확인 가능. 기능 로직 무변경이라 회귀 위험 낮음.

## 4. 안전장치 / 리스크
- **로직 불변**: 사주 계산·천간합충·DB·동의 흐름은 건드리지 않음(CSS·마크업·색만).
- **Streamlit 제약 유지**: 입력칸 자동 포커스 이동은 여전히 불가 → 한 칸 입력 유지(인수인계 교훈 반영).
- **빌드/서명/push는 사용자 직접**(샌드박스에 Flutter SDK·서명 없음).
- 검증: 변경 후 주요 화면 렌더 확인 + 파싱/기능 스모크 체크.
